## 2. 训练确实发生了什么

- 初始化为已保存的在线 SFT 适配器 `3a5dd3e29427d2bf5fc89e813ff16dbd30bdca6339ad2fd4169b6c2b6f024764`，其来源仍是 v18；没有更换基座，也没有从随机 LoRA 开始。
- 基座固定为 `Qwen/Qwen2.5-7B-Instruct@a09a35458c702b33eeacc393d103063234e8bc28`。
- 200 个合成训练 episode 展开为 880 条监督样本，38 个 dev episode 展开为 148 条；训练 loss 评估抽取其中 128 条 dev。参考轨迹由脚本执行并校验，不是客户聊天日志。
- 先完成 4-step 数值冒烟。顺序验收发现新增代码导致重复 shuffle，保留失败记录，修复后复用已完成冒烟；没有增加第二轮 GPU 冒烟。详见 [恢复记录](closeout-shuffle-recovery-20261014.zh-CN.md)。
- 64-step pilot 从旧在线适配器重新建立优化器，不继承冒烟权重或优化器。单次 shuffle 的顺序哈希为 `6fa073e0b76ebacfe51b75a006cff83ab80d321ab52eeab7ecb36a998a897284`。
- 64 步实际访问 512 条样本，覆盖全部 16 个类别；不是完整训练 880 条的一整个 epoch。训练、dev 编码均无跳过，LoRA 参数与梯度累积使用 FP32。
- 训练循环约 701 秒，峰值显存约 14.08 GiB；dev loss 从 0.2299 降至 0.06635。这些数值不能替代任务通过率。
- 新适配器 SHA256：`0c9da9f747324ed06f4b5184ac7a9b439255e9b5f9a6e7b57789ae6540085e73`，服务模型名 `ecommerce-online-0c9da9f74732`。

旧、新数据复用业务场景，训练集内部也有重复输入；不能宣称全部语义新颖或完全没有模板复用。已有输入审计只证明其检查范围内没有跨 split 的精确输入冲突，不等于没有语义相似性。

## 3. 为什么封存验收只有 10/30

对已经下载的 30 条轨迹做静态审计，没有新增模型调用、改规则或重跑封存测试：

- 20 个失败案例都出现 `target_needs_clarification`；其中 2 个案例还出现预设读工具故障的 `tool_failed`。
- 代表性案例中，模型已经正确调用订单查询，并传入匹配的订单 ID 请求 `preview_cancel`；服务端有限目标语法不能识别用户表达，预览被拒绝，后续确认事件也就没有申请可处理。
- 例如“想撤销空气净化器这笔订单，请帮忙处理。”含有明确商品，当前 `target_binding.py` 的有限表达模式仍未覆盖。“取消金额 89.00 元的那一笔。”这类后续消歧也依赖前一轮目标能被识别。
- 因而这是模型与工程控制器共同组成的系统验收失败。不能把全部失败归为模型不会选工具，更不能认为只要继续 SFT 或 GRPO 就会自动修好服务端语法。
- 多订单场景中仍能看到模型过早选第一笔订单的尝试；保护层阻止写入不等于推理正确。20 个案例共有阻断因素，也不代表它们没有其他问题。

知识 dev 剩余失败为 `knowledge_restart_policy`：重启后切换到新问题，回复出现引用字符串，但这一轮没有新的检索和对应 `sources` 证据，评分为缺少当前轮引用。没有检索基础设施故障。当前引用检查也不证明每句话都被证据语义支持。

后续如另开改进任务，应先在 CPU 上设计并验证更完整的意图/商品/金额绑定与多轮消歧，保留归属、金额、版本和按钮确认约束，再决定是否存在模型训练问题。已查看的 30 题只能成为已知回归案例；未来评价泛化需要另建并冻结新的验收数据。此文档没有执行这轮新改进，也没有放松保护层来制造测试提升。

## 4. 实际网页验收

推理运行在服务器；本机只加载 tokenizer 做上下文预算并运行网页业务服务，通过 `127.0.0.1:8000` 的 SSH 隧道请求 BF16 模型。浏览器后台是新建的独立模拟数据库。

实测输入“帮我取消耳机订单”后：

1. 显示 `order_A`、预计退款 199 元及“确认取消”卡片；确认前仍显示已付款。
2. 确认后显示“订单已取消”和“退款处理中，尚未确认到账”。
3. 刷新页面后，会话、取消结果和订单状态保留。
4. 只读数据库检查确认只有一条取消记录、一条 199 元 pending 退款；键盘仍已付款，鼠标仍已发货。

浏览器所用 12 个服务源码文件逐项匹配服务器评测记录的哈希。页面刷新恢复与 HTTP 脚本中的服务进程重启分别记录，不混为一次测试。限定路径通过不代表任意自然语言都能正确处理。

本机证据位于 `outputs/closeout-browser-acceptance-20261014-r1/`：

- `browser-acceptance-receipt.json`：实际 UI 检查及数据库结果。
- `browser-after-reload.jpg`：实际刷新后截图。
- `inference-health.json`：接通时的实际适配器、提示词、工具及知识索引身份。
- `sealed-test-static-audit.json`：保存轨迹的静态审计，不含新模型测试。
