# 当前实例的一次性收尾计划

用户希望把已知需要 GPU 的工作集中在现有 Featurize 实例（端口 46739）完成，避免因为漏做验收而退机后重新租用。

此前“可以释放”的建议仅依据本轮结果已备份，没有覆盖后续候选验收；当前应保留实例，直到下面的一轮收尾结束。本文件是待实施计划，不表示新增训练或评测已经发生。

## 已知状态

- 原 v18 与在线补训候选都已备份；新配置业务 dev 为 39/57→54/57。
- 剩余问题是首轮唯一商品未预览、语言确认后未重新预览，以及知识问答切换后缺少当前问题的证据。
- 两批 RL 诊断都没有组内奖励差异，本轮不再重复相同采样，不启动 GRPO。
- 现有 pilot 入口绑定旧四工具 compact 协议；新知识工具需要匹配的数据、训练收据与评测协议，不能直接照旧命令重训。

## 顺序与范围

1. **先做回归筛查，同时在本机准备数据。** 原 v18 和保存的在线候选，在原九工具 dev 中按 30 个场景各取 2 题，做同协议配对筛查（共 120 条轨迹）。这不是完整 600 题回归，也不是独立 test。若明显退化，记录边界并调整训练中的回放比例；不会自动追加完整 600 题。
2. **一轮定向 SFT。** 从保存的在线候选继续，以新 ID、独立表达和经过验证的参考轨迹补唯一目标、多轮重新预览与知识证据场景，并混入常规业务回放。新训练/开发输入审计和 token 长度检查必须通过。最多一个 4-step 冒烟和一个 64-step pilot，分别保存，不覆盖原模型，不继承冒烟优化器。
3. **同协议开发对照与选择。** 在固定新运行时、相同工具集合与生成配置下重新比较旧候选和新候选，分别报告业务和知识效果。旧 54/57 不能直接与变更了提示词或工具的成绩相减。根据 dev 选择最终候选；一轮无收益时可保留旧候选。
4. **冻结候选后做最终验收。** 执行封存的合成测试一次，并做网页查询、预览、按钮确认、重启恢复的实际联调。测试结果不回流到本轮训练，不根据 test 反复改模型或规则。有限目标语法的未覆盖表达必须如实记为范围缺口；不能为了通过已知测试模板而扩写规则，再宣称测试独立。
5. **备份与退出。** 保存新适配器（若产生）、训练数据/配置/收据、dev/test/回归结果、日志、未解决问题及复现命令。下载并校验，确认要保留的环境镜像后，再释放当前实例。

原 v18 的九工具/RL 分支与在线候选分开保留。若线上模型仅用于四/五工具协议，九工具筛查用于了解能力变化，不把工具协议切换导致的退化误称为 RL 失败，也不强迫两个适配器承担同一角色。

## 退出标准

退出依据是这一轮的训练与验收证据完整，而不是强制所有案例满分：

- 每个已安排阶段有完成或失败收据，原始结果保留。
- 候选选择基于 dev；测试只验收一次，不用来挑模型。
- 生产安全与限定职责不满足时不晋升，保存失败原因。
- 本机备份能校验，权重与环境有可恢复来源。

本轮最多一次定向 pilot。出现新问题不会自动无限追加训练；把结果和局限记录完整后收尾。未来扩展属于新的实验范围，不作为本次遗漏的验收工作。

## 时间口径

已知上一轮 64-step 训练循环约 9 分钟，当前业务/知识配对评测约 12 分钟，80 条旧协议采样约 18 分钟。新的数据量、序列长度与回归难度尚未测量，不能承诺固定结束时间。先用短回归与冒烟实测速度，再更新剩余预算；不先承诺几小时完成或自动扩展长实验。
