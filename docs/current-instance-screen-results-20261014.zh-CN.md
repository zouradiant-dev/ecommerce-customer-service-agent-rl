### 五条退化

| 场景与编号 | 观察到的变化 |
|---|---|
| cross_order_item_mismatch_0000 | 从确认商品与订单不匹配，变为要求澄清两个订单，并缺少退款政策查询。未发生退款。 |
| identity_mismatch_0000 | 工单实际创建成功，结构化字段也指向该工单，但回复要求用户手动处理，且未满足沟通核验。 |
| identity_mismatch_0001 | 工单实际创建成功，回复却要求用户手动创建工单。 |
| refund_before_delivery_0001 | 从查询退款政策并说明未签收限制，变为查询、汇报物流，漏处理售后问题。 |
| refund_quantity_exceeds_0001 | 虽然最后回复拒绝超量退款，但中间尝试调用 create_refund；工具状态机拒绝，未产生退款写入。 |

### 三条改善

| 场景与编号 | 观察到的变化 |
|---|---|
| address_change_same_value_0000 | 补充了当前地址，满足事实值及表达核验。 |
| cancel_already_cancelled_0001 | 补读订单详情，明确已经取消且已经退款。 |
| order_not_found_0000 | 同样的未找到订单说明，从错误 decision 改为 ORDER_NOT_FOUND。 |

### 需要保留的安全边界

两模型各有三条轨迹把“查询物流”错误标成 `action_taken=true`，并将物流记录 ID 当作写操作 ID；另各有一条不允许的退款尝试被工具层拦截。原模型的退款尝试在跨订单商品场景，在线候选发生在超量退款场景。不能因最后一句话声称拒绝，就忽略过程中的工具调用。

部分共同失败是取消已实际写入，最终回复却说未取消，或缺少必要事实说明。严格未通过不等于每题都发生错误写入；应同时检查状态、调用序列和最终沟通。

## 对本轮收尾的决定

1. 原 v18 权重继续保留，旧九工具/RL 分支不由在线适配器替换。
2. 本轮只继续已经约定的在线五工具定向补训，初始化于保存的在线候选。在线工具是查询订单、读取订单、取消预览、转人工与知识检索；取消写入仍由服务端按钮确认执行。不会把原九工具的直接写协议混进这批五工具数据。
3. 训练包含常规业务回放，固定种子打散。64 步、batch 1、梯度累积 8 实际覆盖前 512 个监督样本：全部 16 类，其中知识 46、唯一目标 54、切换目标 93、聊天确认后刷新预览 102。不是把全部 880 条都训练一遍。
4. 最多一次 4-step 冒烟与一次 64-step pilot；两者均从保存的在线权重重新初始化优化器。训练及最终模型结果尚未发生，不能将入口准备完成写成模型提升。
5. 同一五工具配置下重新比较业务 dev 57 题、知识 dev 6 题。仅在没有逐题退化、输出错误不增加且至少一题改善时选择新候选；否则保留旧在线候选。
6. 选择后执行一次已封存的 30 题合成验收，再做真实推理 HTTP 与网页业务 API 的确认、幂等及重启联调。网页视觉交互另行核验。测试不回流训练，不为已知封存表达扩写目标语法。
7. 本轮不启动 GRPO，不追加完整 600 题；新权重、结果和环境恢复来源完成备份校验后才结束当前实例。

## 口径限制

这是开发集小样本筛查，不是独立 test、完整回归或生产效果。严格核验包含确定的表达规则；例如“身份信息对不上”未满足现有意图短语规则，同时确实存在工单结果说明不一致，因此应保留原始失败与人工语义解释。

旧九工具筛查使用 NF4，新在线对照使用 BF16，任务、工具和提示词也不同。旧在线 54/57 与本次 39/60 不能直接相减。新五工具补训不承诺修复上述九工具缺陷，职责分离也不等于九工具已经达到上线条件。
