# 冻结系统的留出合成 Test：52/60，泛化尚未解决

2026-10-15，在模型、提示词、工具、知识库和业务控制器保持冻结的条件下，另行编写并执行 60 条合成挑战题，严格任务通过 **52/60（86.7%）**，低于执行前约定的 90% 门槛。本轮没有训练或修改系统，没有用失败题调参后替换分数。

之前的 30/30 是另一组组合验收，其中有 6 条首轮文本复用旧训练；本次 52/60 是不同数据集上的结果，不能把两者相减当成能力回退，也不能把它们相加计算准确率。更不能把 10/30→52/60 描述成同一独立测试集上的提升。

## 测什么，固定什么

模型仍为 `Qwen/Qwen2.5-7B-Instruct`，基座 revision `a09a35458c702b33eeacc393d103063234e8bc28`，适配器 SHA256 `0c9da9f747324ed06f4b5184ac7a9b439255e9b5f9a6e7b57789ae6540085e73`。系统配置是 `binding_catalog_v6`，与此前最终验收的服务端源码逐文件核对一致；temperature=0、max_tokens=512、输入预算 8192、recent_turns=6。

推理使用端口 64710 实例上的真实 SFT 模型，通过本机 SSH 隧道 `127.0.0.1:8647` 调用；会话编排、工具执行和评分在本机，每题使用隔离的模拟订单库。没有调用真实订单或支付接口，也没有重新做浏览器、吞吐量或并发验收。

新题的发言和业务期望单独编写，未调用训练数据的 `episode()` 或旧模板生成器，未使用模型或目标解析器产生标准答案。标准答案来自明确的业务状态、用户需求及预先指定的按钮事件。金标只进入评分器，不加入模型上下文。

这里的“留出”指未参与当前版本训练、提示词修改或控制器选择。出题者仍是了解项目的同一个代理；这不是独立人工出题或真实用户分布，业务任务语义也必然与训练共享。不能宣称已经完成生产泛化认证。

## 结果

| 切片 | 通过/总数 | 观察 |
|---|---:|---|
| 新商品目录 | 10/10 | 对新完整商品名称可完成查询、预览、按钮确认 |
| 自然表达变化 | 5/8 | “关掉”“不需要了”“终止交易”等被规则层拒绝 |
| 目录目标匹配 | 7/8 | 一条保留 A、取消 B 的需求被模型选错，后端拦截 |
| 多轮组合 | 8/10 | 两条聊天确认/省略目标的后续发言未生成有效新预览 |
| 否定、查询与权限 | 11/12 | 一条否认取消要求的发言错误生成预览 |
| 异常恢复 | 6/6 | 模拟超时、未知结果、过期、版本变化、重复确认等通过 |
| 知识与人工接管 | 5/6 | 一条功能说明未检索，且实际回答有事实错误 |

共调用真实模型 229 次、工具 158 次；模型输出格式错误和基础设施错误均为 0。账本检查中越权写入、错单写入、重复写入及退款金额错误均为 0。**这不表示所有意图判断都安全：一条明确否认取消的输入生成了不应出现的待确认卡片。** 因为没有按钮确认，最终订单没有被取消。

## 8 个失败如何定位

| ID | 证据与归因 | 下一阶段应验证的方向 |
|---|---|---|
| heldout_012 | 跑步机“订单给我关掉吧”：模型尝试预览，词法控制器返回 `target_needs_clarification` | 扩展意图表示或引入受约束的结构化意图提议；不能只补一道题的正则 |
| heldout_013 | 儿童安全座椅“订单不需要了”：同样被控制器拒绝 | 区分间接取消与否定取消，保留有疑问时澄清 |
| heldout_014 | 冲牙器“终止交易”：模型尝试预览，控制器拒绝 | 用新的开发数据覆盖同义表达，先证明规则或协议问题是否能解决 |
| heldout_021 | “我只要硬盘收纳包，移动固态硬盘这笔撤单”：模型查询并预览了收纳包；后端返回 `target_order_mismatch` | 这是模型选目标错误；训练/提示词实验应包含保留目标与取消目标的对照，硬校验继续保留 |
| heldout_030 | 灯光控制器取消后重启，用户“我确定要取消这笔购买”：模型查对订单并尝试预览，绑定层返回 `target_not_found` | 受约束地保留未撤回的目标，明确新的聊天确认只能重建预览 |
| heldout_033 | 车载吸尘器取消后，用户要求看确认页面：旧卡失效，模型未调用新预览 | 模型的多轮动作规划问题，与 030 的控制器拒绝分开处理 |
| heldout_041 | “刚才说取消口袋打印机的是别人，我没有提出这个要求”：模型和规则均未正确识别否认，生成待确认卡 | 优先修复否认/转述的意图作用域；把“不误建预览”与“不发生写入”分成两个指标 |
| heldout_055 | 询问预览按钮含义：没有 `search_policies` 或引用；回复还把确认按钮说成只生成预览 | 知识检索触发和引用一致性要评测；补充回答事实正确性检查，不能只看有无 citation |

055 的事实错误来自逐条查看原始回答后的人工式复核，不是自动评分器已经具备通用语义评判能力。自动失败项仍保留为漏检索、漏引用，没有改变原始得分。

## 防泄漏审计的范围

- 扫描本机可用的 56 份历史 JSONL，包括 v18 数据、在线补训输入，以及之前已看过的开发/验收集合：共 60,979 行，其中 60,969 行能提取用户文本；剩余 10 行是政策和检索标签文件。历史用户文本去重后为 4,388 条。
- 新测试的所有用户发言与这些文本在 NFKC、大小写及标点归一化后，完全重复数为 **0**。
- 每条首轮发言保存字符二元组近邻及序列相似度；最高字符二元组 Jaccard 为 0.2857。这是词面近似，不是语义独立证明。
- 对可用的 21 份含 messages/tools 的监督文件，提取 50,891 个 assistant 监督前缀（43,167 个去重前缀），与本次 229 个真实生成请求做规范消息/工具精确比对，碰撞为 **0**。这不是 tokenizer 渲染等价或 embedding 语义去重。
- 无法审计缺失的历史文件或基座预训练数据。不同系统提示、工具模式、状态或 ID 本身也会使完整输入不同，因此不能用输入哈希无碰撞取代文本和分布审查。

## 执行中断及证据保留

第一条模型调用和业务步骤完成后，新增账本审计脚本把相对路径转换为文件 URI 时失败。第一条的 4 次模型调用、完整轨迹和数据库均保留。只修复评测记录程序，再继续第 2～60 条；模型、提示词、服务端和题目没有变化，没有重放第一条。

`postprocessing-recovery.json` 保存恢复前调用日志 SHA256 和调用数；最终审计再次校验这 4 条原始调用字节一致，全部 60 题各只有一组按序模型调用。原始报错日志和修复前评测脚本也在归档中。4 个评测器工程测试通过，覆盖误取消、重复写入、退款金额和区间计算。

源码入口：

- `scripts/prepare_heldout_system_test.py`：冻结当前已选系统、单独编写案例、历史文本审计；不调用模型。
- `scripts/run_heldout_system_test.py`：身份及源码校验、一次性执行声明、真实模型请求记录、隔离业务状态评分；禁止直接重跑已经消费的测试。
- `scripts/finalize_heldout_system_test.py`：实际请求输入审计、完整报告、SQLite 和归档逐文件验证。

本轮案例与封存协议位于 `outputs/heldout-system-cases-20261015-r1`，原始请求、状态和逐题结果位于 `outputs/heldout-system-real-20261015-r1`。报告与归档校验收据保存在 `outputs/heldout-system-backup-20261015-r2`。归档不含约 14GB 基座或完整软件环境；选中适配器沿用已有已验证备份。

## 后续决策

这次 Test 完成了当前版本的一次留出检验，结论是**有用的受约束客服工程原型，但开放表达和多轮泛化仍有缺口**。不能因为没有错单写入就宣称所有场景可用，也不能因为 8 个失败就直接决定再训练。

下一阶段先在本机整理这些已消费失败为回归案例，另建开发集：优先处理否认误建预览，再拆分词法误拒、模型选目标错误、多轮动作缺失和知识回答错误。分别用开发实验判断修改控制器、上下文、提示词或定向 SFT 的必要性。若比较下一版的泛化效果，需要另外封存的新留出集；不得修完这 8 题后重跑本集，将其重新包装成独立 Test。GRPO 的必要性仍须单独通过采样方差与奖励可辨识性检查，本轮没有启动 GRPO。
